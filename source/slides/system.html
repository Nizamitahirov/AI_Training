SİSTEMİN İŞ PRİNSİPİ (4 dəq). Bu slaydı praktiki hissənin “xəritəsi” kimi təqdim edin. Animasiya: narıncı “paket” ideyadan başlayıb hər dayanacaqda formasını dəyişir - ideya → SPEC.md → commit → kod → deploy → link. Paket hərəkət etdikcə hər addımı adlandırın. Restoran analogiyası: 1) SİZ - müştərisiniz: nə istədiyinizi deyirsiniz (“İşçilərin performansını qiymətləndirən sadə sistem istəyirəm”). 2) CLAUDE (çat) - sizin istəyinizi ətraflı RESEPTƏ çevirir: SPEC.md faylı. Orada hansı ekranlar olacaq, hansı düymələr, hansı məlumatlar saxlanacaq, dizayn necə olacaq - hamısı yazılır. 3) GITHUB - MƏTBƏX: resept (SPEC.md) bura qoyulur, hazırlanan “yemək” (kod) də burada saxlanır. 4) CLAUDE CODE - AŞPAZ: Google Cloud Shell-də işləyir. Mətbəxə (repoya) daxil olur, resepti oxuyur və yeməyi hazırlayır - kod fayllarını yazır, anbarı (Firebase verilənlər bazasını) quraşdırır və hamısını repoya əlavə edir. Cloud Shell sayəsində ona həm GitHub-a, həm də Google/Firebase layihəmizə tam giriş veririk. 5) VERCEL - ZAL və OFİSİANT: hazır yeməyi qonaqlara təqdim edir. Repoya bağlıdır; mətbəxdə yeni yemək hazır olan kimi, onu avtomatik zala çıxarır. Texniki termin: “avtomatik deploy”. 6) İSTİFADƏÇİ - qonaq: sadəcə linki açır və tətbiqdən istifadə edir. Dəyişiklik dövrü: nəyisə dəyişmək istəyəndə əl ilə kod yazmırıq - Claude Code-a sadə dillə deyirik. O, kodu dəyişir, GitHub-a yazır, Vercel saytı 1–2 dəqiqəyə yeniləyir. Firebase: əgər tətbiqdə çox istifadəçi eyni məlumatı görməlidirsə (məs. hamının quiz cavabları, ümumi reytinq), məlumatı mərkəzi yerdə - buludda saxlamaq lazımdır. Firebase bu “anbardır”. Bu gün praktiki layihəmiz də Firebase ilə qurulur - eyni təlimin əvvəlindəki quiz kimi, harada hamı bir-birini real vaxtda görürdü. Restoran analogiyasında Firebase - anbardır: bütün masalara eyni ərzaq oradan gəlir.
